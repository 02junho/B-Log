점검 시 열린 PR은 없었다. 팀원의 미공개 로컬 작업은 확인하지 않았다.
사용자가 문서 제출 완료를 알렸으나 대회 최종 제출 상태는 별도 확인 대상이다.

후속 브랜치 `codex/review-flow-hardening`에서는 검수 화면에 `mode="review"`를 적용해
검수 URL 복사를 유도하던 공유 버튼을 제거했다. 발행 전 내용 확인 체크와 요청 중 중복 실행 방지도 추가했다.
확인 체크는 UI의 의사 확인이며 서버의 소유자 검사나 검수 증명을 대체하지 않는다.

**다음 최우선 과제:** 검수 페이지는 현재 인증 없이 세션 UUID로 초안을 읽는다.
업로드·발행 UI는 팀원이 추가한 액세스 코드/sessionStorage 방식을 사용하고 있어,
서버용 토큰을 브라우저에 전달하지 말라는 기존 가드 지침과도 맞지 않는다.
GitHub OAuth와 사용자별 데이터 접근 제어로 이 두 부분을 함께 교체해야 한다.
이번 변경이 이 접근 제어 문제를 해결한 것은 아니다.

브라우저 점검: 합성 fixture·가짜 confirm 응답으로 공유 버튼 분리, 확인 전 발행 불가,
요청 중 비활성화, 실패 후 재시도, 성공 후 공개 링크, 모바일 가로 넘침을 확인했다.
실제 로그 업로드·유료 분석·발행은 실행하지 않았다.
전체 회귀 테스트는 75개 통과(선택 실로그 2개 제외), 타입 검사 통과.

## 구현 범위

- `/`: 서비스 소개와 동작하는 데모 진입 링크.
- `/p/sample-login-fix`: DB 없이 기존 합성 fixture로 표시. 합성 데이터임을 명시하고 예시 커밋 링크는 비활성화.
- `/p/[slug]`: 서버에서 `published_at`이 있는 `portfolios.view`만 조회. 원본 세션 로그는 조회하지 않음.
- 4단계 요약, 하이라이트와 선정 근거 펼치기, 단계 필터, 타임라인 인용·커밋, 통계·도구·분석 등급.
- 링크 복사 및 클립보드 거부 시 수동 복사, 로딩·오류·없는 페이지·빈 기록 처리, 모바일 화면.
- 기존 `PortfolioView` 계약 유지. 저장 데이터 표시 전 검증, 한글 slug 지원, GitHub 커밋 URL 제한.
- 이벤트 수를 기여도 점수로 표시하지 않으며 기록이 0개이면 비율 막대를 채우지 않음.

## 연결할 작업

1. P2: `GET /api/sessions/[id]/review`와 소유자 인증을 구현하고 응답 계약을 합의한다. 마스킹된 미리보기, 검수 상태, 확정 요청 및 실패 처리 방식이 필요하다.
2. P2·P3: 현재 즉시 발행 경로를 검수 확정 후 발행 흐름으로 연결한다. 프론트엔드의 버튼만으로 검수를 강제하지 말고 서버에서도 확인한다.
3. P2: GitHub OAuth를 연결한다. `BLOG_API_TOKEN`은 서버·CLI 전용이며 클라이언트 코드에 전달하지 않는다.
4. 역할 B·P3: 이 브랜치 통합 후 실제 발행 slug로 화면 E2E 및 Preview 배포 확인. 업로드·진행·검수 화면을 이어서 구현한다.
5. P4: 데모로 공개할 데이터를 검수하고 마스킹 품질 및 인용 프롬프트를 개선한다.

Step 7 전체 완료나 배포 완료로 표시하지 않는다. OG 이미지와 실제 데이터 E2E도 남아 있다.
