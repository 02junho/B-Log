# B-Log 화면 구현 현황과 서비스 완성 가이드

기준: 2026-09-12, `codex/public-portfolio-ui` 브랜치.

> **후속 현황:** 아래는 PR #13 당시 가이드다. main `03b53a2`에서는 PR #14~17의
> 업로드·분석 진행, 검수·확정 발행, OG 이미지, 커밋 매칭 표시까지 구현됐다.
> 검수 GET API 대신 서버 검수 페이지가 추가됐으며 OAuth·소유자 검사는 아직 없다.
> 최신 위험 요소와 우선순위는 [인수인계 최신 점검](FRONTEND_HANDOFF.md)을 우선 참고한다.

## 1. 우리가 만드는 서비스

B-Log는 AI 코딩 세션 로그와 Git 커밋을 분석해 개발자의 판단과 AI 활용 과정을 증명하는 포트폴리오 생성 서비스다.
사용자는 기록을 입력하고, 분석·마스킹 결과를 검수한 뒤 공유 링크를 발행한다.
독자는 문제 정의 → AI 지시 → 근거 탐색·의사결정 → 실패·복구를 대화 인용과 커밋으로 확인한다.

목표 흐름은 **로그인 → 기록 입력 → 분석 진행 → 공개 전 검수 → 발행 → 공유 페이지**다.
이번 구현은 이 흐름 중 **서비스 소개와 마지막 공유 페이지**에 해당한다. 웹에서 분석을 시작하는 서비스 전체가 완성된 상태는 아니다.

## 2. 이번에 만든 페이지

| 주소 | 대상·목적 | 현재 동작 |
| --- | --- | --- |
| `/` | 처음 방문한 사용자에게 서비스 소개 | 소개 문구와 합성 데모 진입 링크 제공. 분석 시작 버튼은 아직 없음 |
| `/p/sample-login-fix` | 사용자·팀원이 결과 화면을 미리 확인 | 기존 합성 fixture로 표시. DB 없이 동작하며 실제 분석 결과가 아님을 안내 |
| `/p/[slug]` | 공유 링크를 받은 채용 담당자·심사위원 | 서버에서 발행된 `portfolios.view` 조회. 실제 발행 데이터의 화면 E2E는 아직 미검증 |

공개 화면에는 네 단계 요약, 하이라이트와 선정 근거, 단계별로 걸러 볼 수 있는 타임라인,
대화 인용·커밋, 사용 도구·분석 등급, 기록 통계, 링크 복사가 있다.
모바일 배치와 로딩·오류·없는 페이지·빈 기록 상태도 구현했다.
합성 데모의 커밋은 실제 저장소 링크처럼 연결하지 않는다. 이벤트 수는 사람과 AI의 기여도 점수가 아니다.

로컬 확인: `npm run dev` 실행 후 `http://localhost:3000/p/sample-login-fix` 방문.
서버를 다른 포트로 실행했다면 해당 포트를 사용한다. 실제 공개 데이터 조회에는 Supabase 서버 설정이 필요하다.

## 3. 현재 있는 백엔드와 아직 없는 사용자 흐름

| 영역 | 현재 구현 | 필요한 연결 |
| --- | --- | --- |
| 업로드 | `POST /api/upload`, 파일·프로젝트명·공개 저장소 URL 입력 계약 | 파일 선택·입력 검증·오류 안내 화면 |
| 분석 | 잡 실행·상태 조회 API, 파싱·태깅 파이프라인 | 진행 상태, 다음 잡 연결, 실패·재개 처리 |
| 발행 | `POST /api/sessions/[id]/publish`, 매칭·마스킹·저장 | 검수 확정 후 발행하도록 서버 흐름 변경 |
| 공개 조회 | 이번 `/p/[slug]` 화면 | 실제 발행 데이터 및 배포 환경 검증 |
| 인증 | 현재 API는 임시 서버 토큰 가드 사용 | GitHub OAuth, 사용자별 세션·잡 접근 제어 |
| 검수 | 검수 GET API·화면 미구현 | 마스킹된 미리보기와 사용자 확인, 서버의 확정 상태 검증 |

백엔드 프로덕션 E2E 완료는 기존 ROADMAP의 9/10 기록이다. 이번 UI 검증에서 실서비스 분석·발행을 다시 실행한 것은 아니다.

## 4. 다음 구현 순서와 완료 조건

### 1순위: 인증과 검수·발행 계약 확정 — P2, P3

- GitHub OAuth 로그인·로그아웃, 취소·실패 안내를 연결한다.
- 사용자 본인의 프로젝트·세션·잡만 조회하거나 실행할 수 있도록 서버에서 검사한다.
- `GET /api/sessions/[id]/review`의 응답 및 검수 확정 요청 방식을 합의한다. 이는 예정 API이며 아직 존재하지 않는다.
- 분석이 끝난 비공개 미리보기를 준비하고, 검수 확정 전에는 공개 저장·조회되지 않게 한다.
- `BLOG_API_TOKEN`을 브라우저에 넣어 기존 API를 호출하는 방식은 사용하지 않는다.

완료 조건: 로그인한 사용자가 본인 기록만 접근하고, 미검수 결과는 발행되지 않는다.

### 2순위: 입력과 분석 진행 화면 — P3, P2

- Claude Code·Codex 로그 파일 선택, 프로젝트명·공개 GitHub 저장소 URL을 입력한다.
- 범용 대화록은 별도 LLM 구조화 입구가 연결될 때 지원 상태를 표시한다. 구현 전에는 동작하는 기능으로 안내하지 않는다.
- 업로드 성공 후 받은 세션·잡 ID로 상태를 조회한다. `nextJobId`와 `continue` 계약에 맞춰 후속 처리를 연결한다.
- 단계·진행률·실패 이유를 표시한다. 중복 실행, 재시도, 화면 새로고침 후 진행 복원 동작을 정한다.
- 랜딩의 분석 시작 진입점을 실제 화면에 연결한다.

완료 조건: 사용자가 브라우저에서 개인 프로젝트 로그를 넣고 분석 완료 또는 실패 이유를 확인한다.

### 3순위: 마스킹 검수와 발행 — P4, P2, P3

- 정규식 마스킹 보강과 LLM 검출 결과를 반영한 비공개 미리보기를 제공한다.
- 사용자가 공개될 인용·요약·커밋과 민감정보 잔존 여부를 확인하도록 한다.
- 수정·제외 기능의 지원 범위를 팀에서 결정하고 검수 API와 맞춘다.
- 검수 확정 후에만 발행하며, 중복 클릭·실패·재요청 시 일관된 결과를 반환한다.
- 발행 응답의 `path`로 이동하고 링크를 복사한다.

완료 조건: 검수하지 않은 상태에서는 서버가 발행을 막고, 확정한 결과만 공개 링크에 나타난다.

### 4순위: 실제 사용 검증과 제출 준비 — 전원

- 개인 프로젝트 로그로 로그인부터 공유까지 한 번에 검증한다.
- 로그아웃한 다른 브라우저에서도 발행된 링크를 확인한다. 비공개 기록은 접근할 수 없어야 한다.
- 모바일 입력·진행·검수, 실패 복구와 긴 텍스트를 확인한다.
- 내 포트폴리오 목록, OG 이미지, 검수된 데모 3종, 제출용 스크린샷을 준비한다.
- Preview 배포와 운영 환경에서 동일한 흐름을 확인한다.

완료 조건: 개발자 도구나 수동 API 호출 없이 사용자가 입력부터 공유까지 끝낸다.

## 5. 역할 B의 후속 작업

@Aio1135는 Codex 어댑터·fixture·실로그 검증에 더해 이번 공개 UI를 지원했다.
P3 전체 담당을 변경한 것은 아니다. 우선 이 PR의 리뷰와 기존 프론트 작업 통합을 지원하고,
P2 인증·검수 계약이 준비되면 실제 Codex 로그의 분석 결과가 공개 화면까지 연결되는지 검증한다.
다음 화면 구현 담당은 P3와 조율하되, 공개 화면만 보고 서비스 전체 완료로 보고하지 않는다.

## 6. 유지할 범위와 검증 기록

- 입력은 Claude Code·Codex·범용 대화록 3개로 제한한다. 추가 도구 어댑터, PDF, 실시간 연동 등은 이번 범위가 아니다.
- 화면은 공통 `PortfolioView`를 소비하고 파서 원문이나 도구별 전용 데이터 구조에 의존하지 않는다.
- 실제 세션 로그·환경 파일·키는 커밋하지 않는다.
- 이번 변경: 테스트 74개 통과(선택 실로그 2개 제외), 린트·타입 검사·빌드 통과.
- 데스크톱·모바일 데모의 필터, 선정 근거 펼치기, 공유, 이동·없는 페이지 확인 완료.
- 실제 발행 데이터 화면 E2E, OAuth·검수, 배포 확인은 미완료다.
